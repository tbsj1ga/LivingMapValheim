# MapOverlay — состояние и план

Мод для Valheim: показывает на карте постройки (по материалу) и обработанную
мотыгой землю (тропы, мощение, культиватор). Без Harmony-патчей, только клиент,
ничего не синхронизирует по сети.

Текущая версия: **0.8.0**. Игра: Valheim 1.0.12, BepInEx 5.4.23.5.

---

## Сделано

- [x] **Слой рисуется прямо в текстуру карты.** `RenderTexture` + `Graphics.Blit`
      ванильной карты + отрисовка фигур через `GL` со встроенным шейдером
      `Hidden/Internal-Colored`. Результат *является* картой: панорамируется,
      зумится, попадает под туман войны и под все маркеры, работает и на
      миникарте. В оперативной памяти не держится ничего.
- [x] **Разрешение выше ванильного.** `MapTextureScale`: 2048 (12 м/px, 16 МБ) →
      4096 (6 м/px, 67 МБ) → 8192 (3 м/px, 268 МБ) → 16384 (1.5 м/px, ~1 ГБ).
      Только видеопамять. Если карта отказывает — автоматический шаг вниз.
- [x] **Постройки настоящими footprint'ами.** Берётся `collider.bounds` каждого
      коллайдера, рисуется реальный прямоугольник, а не квадрат фиксированного
      размера. Ограничение 32 м на сторону от случайных гигантских коллайдеров.
- [x] **Цвет по материалу.** `WearNTear.MaterialType`, все 9 значений
      (Wood, Stone, Iron, HardWood, Marble, Ashstone, Ancient, Ice, Timberwood).
- [x] **Тёмная обводка построек.** Отдельный проход перед заливкой, чтобы дом
      отделялся от выровненной площадки под ним.
- [x] **Дорожки по всем трём каналам paint-маски.** `PaintType` в игре — это
      `{ Dirt = красный, Cultivate = зелёный, Paved = синий }`; альфа это маска
      растительности и к типу покраски отношения не имеет. Плюс опциональный
      слой просто выровненной земли (`ShowClearedGround`).
- [x] **Туман войны уважается** — ничего не рисуется там, где игрок не был.
- [x] **Накопление и сохранение.** Свой файл на мир в
      `BepInEx/config/MapOverlay/<worldUID>.bin`. Прошёл один раз — осталось
      навсегда, перепроходить не нужно.
- [x] **Коррекция цветового пространства** (`LinearColorFix`) — иначе цвета
      вымываются при linear-рендере.
- [x] **Минимальный размер фигуры в метрах, а не в пикселях текстуры.** Без
      этого повышение `MapTextureScale` делало мелкие куски *менее* заметными.
- [x] **Безопасность.** Ноль Harmony-патчей; всё в try/catch; дедупликация
      ошибок в логе; глобальный предохранитель (после 25 ошибок мод сам себя
      выключает и возвращает ванильную текстуру); отдельная деградация слоя
      ландшафта; потолки на объём хранимых данных; `OverlapSphereNonAlloc` с
      переиспользуемым буфером.

## Известные ограничения (не баги)

- **Потолок точности — 1.5 м/пиксель.** Карта покрывает 24.6 км; при
  максимальном размере текстуры у видеокарты (16384) это и есть предел. Резче
  можно только отдельным слоем в экранном пространстве.
- **Видно только то, что знает клиент.** Ландшафт грузится позонно, поэтому
  дорожки появляются лишь там, где ты побывал.
- **Данные могут устареть.** Если кто-то снесёт постройку, пока тебя нет рядом,
  она останется на карте до следующего визита.

## План

### 1. Сканирование через ZDO вместо физики — приоритет
Сейчас постройки ищутся через `Physics.OverlapSphere`, а он видит только
инстанцированные коллайдеры, то есть загруженные зоны. У хоста при этом в
памяти лежат ZDO **всего мира** (в логе: 72 871 штука). Переход на `ZDOMan`
даёт:
- вся база и все постройки мира появляются сразу, без обхода ногами;
- снесённые постройки корректно исчезают, потому что набор авторитетный;
- радиус сканирования перестаёт быть ограничением.

Нужно: доступ к `ZDOMan.m_objectsByID` через рефлексию, фильтр по префабам с
компонентом `Piece`, чтение позиции из ZDO, кэш «хэш префаба → материал +
размер», обход порциями по кадрам. Footprint придётся брать из префаба, а не из
живого коллайдера.

### 2. Инкрементальная перерисовка слоя
Сейчас любая правка вызывает полную пересборку: `Blit` всей текстуры плюс все
фигуры заново. На масштабе 8 это гигабайт за раз. Достаточно дорисовывать
только новые фигуры поверх, а полную пересборку делать лишь когда что-то
исчезло. Ожидаемый результат — пересборка перестаёт быть заметной вообще.

### 3. Деревья
Было в исходном запросе. Оговорка: ванильная карта и так рисует лес отдельным
слоем (`m_forestMaskTexture`), поэтому смысл появляется в основном для
показа **вырубленных** участков. Требует отдельного копания в том, как
растительность хранится и в какой момент у неё появляется ZDO.

### 4. Ручной сброс области
Команда или горячая клавиша «забыть накопленное здесь и пересканировать»,
чтобы чинить устаревшие данные без удаления всего файла.

### 5. Уборка
После пунктов 1–2 CPU-путь покраски и экранный слой (`DetailedOverlay`)
становятся мёртвым грузом. Либо удалить, либо оставить как аварийный запасной
вариант, но убрать из конфига лишний шум.

## Инфраструктура проекта

Не про функциональность мода, но про то, чтобы с ним было удобно работать
дальше.

- [x] Локальный git-репозиторий (`git-init.ps1`, `.gitignore`, `.gitattributes`)
- [x] `CHANGELOG.md` с историей версий
- [ ] **Автокопирование DLL в plugins после сборки.** Сейчас файл переносится
      руками, и это ровно тот шаг, на котором легко потестировать старую сборку
      и полдня искать несуществующий баг. Добавить в `.csproj` цель `AfterBuild`
      с `Copy` в профиль r2modman.
- [ ] **Сборка кладёт результат в `build\`.** Сейчас `.csproj` пишет в `bin\`,
      а в `build\` лежит DLL, собранный вручную через `mcs`. Два источника
      правды — так рано или поздно в репозиторий попадёт устаревший бинарник.
- [ ] **Автопроверка сигнатур после сборки.** Скрипт, сверяющий все обращения
      мода в `assembly_valheim.dll` с тем, что реально есть в текущей версии
      игры. Именно такая проверка нашла причину поломки AutoRepair и
      CraftFromContainers; компилятор её не даёт, потому что собирает против
      локальных сборок, а падает всё уже в рантайме при обновлении игры.
- [ ] **`LICENSE`.** Нужен, только если выкладывать наружу. Для модов Valheim
      обычно MIT.
- [ ] **Пакет для Thunderstore** — `manifest.json` (имя, версия, описание,
      зависимость от BepInExPack) плюс `icon.png` строго 256×256, иначе пакет не
      примут. Имеет смысл, только если решишь публиковать.
- [ ] **Разбиение `MapOverlayPlugin.cs`.** 75 КБ в одном файле. Пока терпимо и
      читается, но после пункта 1 плана (сканирование через ZDO) туда добавится
      заметный кусок, и стоит разнести на хранилище / сканер / GPU-слой /
      конфиг.

### Сознательно не делаем
- **Синхронизация между игроками.** Решено на этапе плана: мод локальный.
  Дописывать что-либо в блоб стола картографа нельзя — любой ванильный игрок,
  записав в стол свою карту, стёр бы наши данные, а сам блоб уже ~4 МБ до
  сжатия.
